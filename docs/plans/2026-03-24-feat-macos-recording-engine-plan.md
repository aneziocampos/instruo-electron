# macOS Recording Engine — Phase 2 with AXUIElement

## Overview

Implement the recording engine for macOS, replacing the originally planned Windows UI Automation with macOS Accessibility API (AXUIElement). This builds on the Phase 1 foundation (Electron scaffold, auth, IPC, API client, tray, i18n, pages) which is already cross-platform.

**Key change:** Build a custom napi-rs (Rust) native addon wrapping macOS AXUIElement APIs, since no existing npm package exposes `AXUIElementCopyElementAtPosition`.

(see brainstorm: `docs/brainstorms/2026-03-24-macos-first-pivot-brainstorm.md`)

## Proposed Solution

### Native Addon: `instruo-native` (Rust + napi-rs)

A local Rust crate in `native/` that exposes ~6 functions to Node.js:

```typescript
// Generated TypeScript declarations (auto-generated by napi-rs)
export function checkAccessibility(prompt: boolean): boolean
export function getElementAtPosition(x: number, y: number): ElementInfo | null
export function getParentElement(role: string, title: string, x: number, y: number): ElementInfo | null
export function getProcessName(pid: number): string | null

export interface ElementInfo {
  role: string | null
  subrole: string | null
  title: string | null
  value: string | null
  description: string | null
  help: string | null
  x: number | null
  y: number | null
  width: number | null
  height: number | null
  pid: number
  childrenCount: number
}
```

**Why napi-rs:** Production-proven (Prisma, SWC, Next.js), generates TypeScript types, N-API stable ABI (no electron-rebuild needed), memory-safe Rust.

**Key Rust crates:**
- `napi` + `napi-derive` v3 — Node-API bindings
- `accessibility-sys` v0.2 — Raw FFI bindings to macOS AXUIElement C API
- `core-foundation` v0.10 — Safe wrappers for CFString, CFArray, CFDictionary
- `core-graphics` v0.24 — CGPoint, CGSize for position/size extraction

### macOS Permissions

Two permissions required, both must be granted before recording:

1. **Accessibility** — for `uiohook-napi` (global hooks) + `instruo-native` (AXUIElement queries)
   - Check: `systemPreferences.isTrustedAccessibilityClient(false)`
   - Prompt: `systemPreferences.isTrustedAccessibilityClient(true)` → opens System Settings
   - User must manually toggle in System Settings > Privacy & Security > Accessibility

2. **Screen Recording** — for `desktopCapturer`
   - Check: `systemPreferences.getMediaAccessStatus('screen')`
   - First `desktopCapturer.getSources()` call triggers OS prompt
   - App must be restarted after granting (macOS limitation)

**Permission flow:** Before first recording, show a setup screen with permission status indicators and buttons to grant each one.

### macOS Deep Link Differences

macOS uses `open-url` event (not `second-instance` + `process.argv`):

```typescript
app.on('open-url', (_event, url) => {
  if (url.startsWith('instruo://')) {
    handleDeepLink(url)
  }
})
```

electron-builder handles the `Info.plist` URL scheme registration via the existing `protocols` config.

### Element Detection Priority (macOS)

1. **AX Roles + Subroles** (highest): AXButton → "Click on [Title]", AXCheckBox → "Check [Title]", AXPopUpButton → "Select in [Title]"
2. **AX Attributes**: AXTitle, AXDescription, AXValue, AXHelp for label resolution
3. **Parent Hierarchy Walking**: Walk AXParent to find meaningful container (AXWindow, AXGroup)
4. **Fallback**: "Click on [Window Title]" or "Click at (x, y)"

**Password detection:** `AXSubrole == "AXSecureTextField"` (equivalent to Windows `IsPassword`)

### Platform Abstraction

The `ElementDetector` interface keeps platform-specific code swappable:

```typescript
// src/main/element-detector.ts — interface (already in plan)
interface ElementDetector {
  getElementAt(x: number, y: number): Promise<ElementInfo | null>
  dispose(): void
}
```

- **macOS:** `src/main/ax-client.ts` wraps `instruo-native`
- **Windows (future):** `src/main/uia-client.ts` wraps `node-winautomation`

## Technical Considerations

- **Rust toolchain required for development** — `rustup` must be installed. CI builds via GitHub Actions with `dtolnay/rust-toolchain`.
- **No electron-rebuild needed** — napi-rs produces N-API binaries (ABI-stable across Node/Electron versions).
- **Universal binary** — napi-rs can produce a single `.node` file for both ARM64 + x86_64 via `lipo`.
- **AXUIElement is synchronous** — calls block the thread. Same worker thread pattern as planned for Windows UIA (1-second timeout, fallback title on timeout).
- **CoreFoundation memory management** — `AXUIElementCopyAttributeValue` follows "Create Rule" (caller owns reference). Rust's `Drop` handles cleanup via `wrap_under_create_rule`.
- **macOS DMG distribution** — electron-builder produces `.dmg`, requires Apple Developer cert ($99/year) + notarization.

## Implementation Phases

### Phase 2A: Native Addon (Week 3)

- [ ] **Scaffold napi-rs project** in `native/` directory
  - `Cargo.toml` with `accessibility-sys`, `core-foundation`, `core-graphics`, `napi`, `napi-derive`
  - `build.rs` with `napi_build::setup()`
  - `src/lib.rs` with exported functions

- [ ] **Implement core functions:**
  - `check_accessibility(prompt: bool) -> bool`
  - `get_element_at_position(x: f64, y: f64) -> Option<ElementInfo>`
  - `get_parent_chain(element) -> Vec<ParentInfo>` for hierarchy walking
  - Helper: `get_string_attr`, `get_point_attr`, `get_size_attr`

- [ ] **Integrate with Electron:**
  - Add `instruo-native` to `electron.vite.config.ts` externals
  - Add to `electron-builder.yml` `asarUnpack`
  - Build script: `cd native && npx @napi-rs/cli build --release`
  - Verify `.node` file loads in Electron main process

- [ ] **Test with real macOS apps**
  - Finder, Safari, TextEdit, System Settings — verify element titles and roles
  - Check apps with poor accessibility (games, custom renderers)

### Phase 2B: Recording Engine (Week 4-5)

- [ ] **Recording engine** — `src/main/recording-engine.ts`
  - 4-state machine (idle → recording ↔ paused → review)
  - Capture queue with error boundaries
  - State guard at every entry point

- [ ] **Capture pipeline** — `src/main/capture-pipeline.ts`
  - Eager screenshot on mousedown (before queue)
  - AX element query on worker thread (1s timeout)
  - Screenshot annotation via sharp
  - Write JPEG to temp file
  - Store step metadata (file path, not buffer)

- [ ] **Step store** — `src/main/step-store.ts`
  - In-memory step collection
  - JSONL disk persistence (debounced 1/sec)
  - Crash recovery on next launch

- [ ] **AX client** — `src/main/ax-client.ts`
  - Wraps `instruo-native` with ElementDetector interface
  - Worker thread with 1s timeout
  - Fallback title generation on timeout

- [ ] **Step title generator** — `src/main/step-title-generator.ts`
  - 4-layer priority system adapted for macOS AX attributes
  - Pure function: `(element: ElementInfo | null, action: StepActionType) => string`

- [ ] **Global hooks** — `src/main/global-hooks.ts`
  - `uiohook-napi` setup, start/stop
  - Self-click filtering
  - Left/right click capture, retroactive double-click detection
  - Keystroke debouncing + merge + password masking

- [ ] **Screenshot capture** — `src/main/screenshot-capture.ts`
  - `desktopCapturer` wrapper
  - Multi-monitor support (match display to click coordinates)
  - `NativeImage.toJPEG(80)` output

- [ ] **Screenshot annotator** — `src/main/screenshot-annotator.ts`
  - Red click circle via `sharp.composite()` with pre-generated overlay
  - Constants from `shared/constants.ts`

- [ ] **Hotkey manager** — `src/main/hotkey-manager.ts`
  - `globalShortcut.register('CommandOrControl+Shift+R')`
  - Toggle: idle → start, recording → stop, paused → resume

- [ ] **Permission setup screen** — `src/renderer/src/pages/PermissionPage.tsx`
  - Check Accessibility + Screen Recording status
  - Buttons to open System Settings for each
  - Green checkmarks when granted
  - "Continue" button when all permissions granted

- [ ] **Tray recording states**
  - Wire tray-manager to recording engine
  - Recording/paused icon states + context menus
  - Tooltip with step count

- [ ] **Countdown in main window**
  - 3-2-1 countdown shown in main window before minimizing to tray
  - Esc to cancel
  - Auto-dismiss, then minimize to tray

- [ ] **macOS deep link handler update**
  - Add `open-url` event handler alongside existing `second-instance`
  - Platform detection for correct handler

### Phase 2C: Review & Upload (Week 6-7)

- [ ] **Review page** — `src/renderer/src/pages/ReviewPage.tsx`
  - Two-panel layout: step list (60%) + screenshot preview (40%)
  - Editable titles, delete, up/down reorder
  - Guide metadata: title, AI writer, guide type, team
  - "Discard" with confirmation

- [ ] **Upload flow** (main process orchestration)
  - `guide:upload-all` IPC triggers main process upload loop
  - Reads screenshots from temp files
  - Sequential upload with retry + progress events
  - Pre-upload plan limit validation

- [ ] **Success state**
  - Guide URL link, "Record another" button
  - Clean up temp files

- [ ] **LGPD warning dialog**
  - Show before first recording (store acknowledgment in electron-store)
  - Explain screenshot capture captures all visible content

## Risk Analysis

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| AXUIElement returns poor data for some apps | Medium | Medium | Test top 10 target apps early. Fallback title system. |
| Rust addon build complexity for contributors | Medium | Low | Pre-built binaries via napi-rs CI. Most devs just `npm install`. |
| macOS Accessibility permission UX is confusing | Medium | Medium | Clear permission setup page with step-by-step guidance. |
| Screen Recording requires app restart | High | Low | Show clear message. Check on launch and skip if already granted. |
| `uiohook-napi` requires Accessibility on macOS | Known | Low | Same permission covers both hooks and AX queries. |
